# 9. The 90-Day Study Plan — Using This Entire Repo Systematically

## Who This Plan Is For
Someone with SOME existing background (not necessarily a total beginner) who has roughly 3 months before actively interviewing, and wants a structured way to move through this entire repo rather than randomly jumping between modules.

## Weeks 1-3: Foundations Solid (Modules 01, 02, 03)
```
Week 1: 01-fundamentals (ALL of it) — this is the conceptual vocabulary
        everything else builds on; do not skip this even if some of it
        feels basic, since interview questions constantly reference
        these foundational concepts (SCD, OLTP/OLAP, CAP theorem, etc.)

Week 2: 02-sql files 1-6 (basics through advanced patterns) — practice
        EVERY query in the playground; this is genuinely the most
        heavily-tested single skill area

Week 3: 02-sql files 7-9 + case studies + interview questions
        (optimization, transactions, production) — THEN 03-python
        files 1-5 (fundamentals through database connectivity)
```

## Weeks 4-6: The Full Tool Stack (Modules 03-06)
```
Week 4: 03-python files 6-13 (APIs, cloud SDKs, SharePoint/Graph API,
        PySpark intro, data quality, production practices) — this is
        where "book knowledge" starts becoming "can actually build things"

Week 5: 04-etl-elt (all of it) — understanding WHY tools evolved this
        way (SSIS/Informatica -> ADF/Glue/dbt) builds genuine judgment,
        not just tool syntax memorization

Week 6: 05-databases (all of it) — this is a DENSE module; don't rush
        it, especially the history/evolution files and the "what
        companies actually use" file, which come up constantly in
        interviews
```

## Weeks 7-9: Scale, Cloud, and Operations (Modules 06-10)
```
Week 7: 06-big-data (all of it) — Spark internals and performance
        tuning specifically deserve real attention here, a very
        commonly-probed depth area in interviews

Week 8: 07-cloud-platforms (all of it) — pick whichever cloud is most
        relevant to your target jobs and go DEEPEST there, while still
        reading the others for breadth/comparison fluency

Week 9: 08-orchestration + 09-visualization + 10-devops — these three
        together build your "how does this actually run in production"
        fluency; don't skip DevOps even if it feels adjacent to "real"
        DE work — it's increasingly expected knowledge
```

## Weeks 10-12: System Design & Interview Execution (Modules 11-12)
```
Week 10: 11-system-design files 1-10 — read slowly, this is the
         highest-leverage material for senior-level interviews
         specifically; do the "try it yourself" exercises genuinely,
         don't just read passively

Week 11: Work through ALL 7 case studies in 11-system-design/case-studies/
         YOURSELF FIRST (blank page, no peeking) before comparing your
         reasoning to the provided walkthroughs — this is where real
         judgment gets built, not from reading alone

Week 12: 12-interview-prep (this module) — resume/portfolio polish,
         behavioral story bank preparation, and final review of the
         master-question-bank.md across all modules
```

## A Parallel Track to Run THROUGHOUT All 12 Weeks
```
- Build/maintain a real portfolio project (recap file 2) incrementally
  — don't leave this until week 12
- Do 15-20 minutes of SQL practice most days (small, consistent
  practice beats occasional long cram sessions for pattern-recognition
  automaticity, recap file 5)
- Keep a running personal "story bank" document (file 3) — add a new
  behavioral story draft whenever you recall a genuinely relevant
  past experience, rather than trying to invent 8 stories from
  scratch in week 12
```

## Adjusting This Plan for Your Situation
```
Less time available (e.g., 4 weeks, an urgent job search):
  Compress to: 02-sql (critical) -> 03-python essentials ->
  05-databases key concepts -> 11-system-design (files 1, 2, 8, 10 +
  at least 3 case studies) -> 12-interview-prep — accept you won't
  go as deep everywhere, prioritize breadth of the MOST commonly-tested areas

More experienced, targeting senior/staff roles specifically:
  Spend disproportionately MORE time in 11-system-design and the
  "what companies actually use" files across every module (05, 06, 07,
  08, 09, 10) — these are exactly what differentiates senior-level
  interview performance, per module 11 file 9's discussion
```

## Interview Traps
- Don't treat this plan as rigid — if a specific job posting emphasizes a particular skill (e.g., heavy Kafka/streaming focus), REORDER to prioritize that area regardless of the "default" week sequence above.
- The parallel portfolio-building track is not optional filler — it's what makes your resume (file 2) and your interview stories (file 3) genuinely CONCRETE rather than abstract, and interviewers can tell the difference.
